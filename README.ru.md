# SDSS17: supervised vs unsupervised классификация небесных объектов

[English](README.md) · **Русский**

Техническая часть проекта: сравнение Random Forest (с учителем) и K-Means (без учителя)
на одной задаче — разделение STAR / GALAXY / QSO по фотометрии и красному смещению.

**Главный результат — [`REPORT.md`](REPORT.md):** сводный отчёт со всеми таблицами,
числами и иллюстрациями. Собирается автоматически из сохранённых CSV; ни одно значение
в нём не вписано вручную.

## Быстрый старт

```bash
uv sync
./run_all.sh
```

Полный прогон занимает ~10 минут (основное время — `GridSearchCV` и контрольные
эксперименты). Все выходные файлы перезаписываются, ручных правок между этапами не нужно.

## Данные

`data/raw_sdss17.csv` — оригинальный `star_classification.csv` с Kaggle
([Stellar Classification Dataset – SDSS17](https://www.kaggle.com/datasets/fedesoriano/stellar-classification-dataset-sdss17)),
100 000 объектов. Файл не коммитится (см. `.gitignore`) — скачайте и положите его туда сами.

Если файла нет, `scripts/00_fetch_data.py` запрашивает эквивалентную выборку у первоисточника —
публичного SQL-сервиса SDSS SkyServer DR17 (без регистрации), тем же соединением
`PhotoObj`/`SpecObj` и с той же схемой столбцов. Отличается только конкретный срез строк;
распределение классов получается практически идентичным. Если файл уже на месте,
скрипт ничего не делает.

## Этапы

| Скрипт | Что делает |

| `02_train_supervised.py` | Подход A: `GridSearchCV` (5 фолдов) + Random Forest |
| `03_cluster_unsupervised.py` | Подход B: elbow/silhouette для k=2..8, K-Means k=3, PCA |

и отчёт можно перестраивать без повторного обучения.

## Ключевые решения

- **Признаки:** `u, g, r, i, z, redshift`. Координаты и технические ID намеренно исключены —
  они дают завышенную и физически бессмысленную точность (см. контрольные эксперименты).
- **Идентификаторы читаются как строки.** `obj_ID` и `spec_obj_ID` в SDSS имеют порядок 1.2·10^18,
  что больше 2^53, а в CSV часть значений записана в научной нотации — при автоопределении типа
  pandas берёт `float64` и необратимо теряет младшие разряды. Разные объекты при этом
  склеиваются в один идентификатор, а в выходных таблицах `obj_id` превращается
  в `1.2376609613304302e+18`.
- **Дедупликация — по `spec_obj_ID`, а не по `obj_ID`.** Единица наблюдения здесь спектр:
  именно по нему определён класс, и `spec_obj_ID` уникален на всех 100 000 строк.
  А `obj_ID` ключом не является — у 19 154 строк он повторяется, но при этом различаются
  фотометрия, класс и красное смещение. Дедупликация по нему выбросила бы ~19 тысяч
  полноценных наблюдений (22 % датасета).
- **Очистка:** отбрасываются строки с фотометрией вне диапазона 0..40 mag (в SDSS отсутствующая
  фотометрия кодируется значением −9999) и с `redshift` вне −0.1..10. На Kaggle-версии
  под это правило попадает ровно одна строка, итог — 99 999 объектов.
- **Scaler** обучается только на train-выборке, затем применяется ко всему набору — это
  исключает утечку в оценку Подхода A; Подход B использует тот же scaler.
- **`silhouette_score`** считается на детерминированной подвыборке в 10 000 объектов:
  на полных 100k потребовалась бы матрица расстояний 100 000 × 100 000.
- **Воспроизводимость:** `random_state=42` зафиксирован для split, Random Forest, K-Means
  (`n_init=10`), PCA и подвыборки silhouette. Два полных прогона подряд дают побайтово
  идентичные таблицы; различаются только замеры времени обучения.

## Результаты

Датасет Kaggle SDSS17, 99 999 объектов после очистки (GALAXY 59.4 %, QSO 19.0 %, STAR 21.6 %).

| Подход | Метрика | Значение |
|---|---|---|
| A (Random Forest) | accuracy | 0.9796 |
| A | precision / recall / f1 (macro) | 0.9802 / 0.9722 / 0.9761 |
| A | время обучения | 9.1 с (+ ~230 с на `GridSearchCV`) |
| B (K-Means, k=3) | ARI | 0.2580 |
| B | NMI | 0.3094 |
| B | purity | 0.7340 |
| B | silhouette | 0.4426 |
| B | время обучения | 0.38 с |

Лучшая конфигурация Подхода A: `n_estimators=300`, `max_depth=20` (cv f1_macro = 0.9747).

### Что показали контрольные эксперименты

| Набор признаков | RF f1_macro | K-Means ARI |
|---|---|---|
| рабочий набор (baseline) | 0.9761 | 0.2580 |
| + координаты | 0.9759 | 0.2611 |
| только координаты | 0.5497 | −0.0023 |
| без redshift | 0.8373 | 0.0207 |
| только redshift | 0.9375 | 0.2525 |
| цветовые индексы + redshift | 0.9760 | **0.3133** |

- **Координаты дают утечку.** На одних только `alpha` и `delta` accuracy достигает 0.6865
  против 0.5945 у тривиального предсказания самого частого класса. Физики за этим нет:
  модель запоминает геометрию обзора. Это и есть причина, по которой координаты исключены.
- **Красное смещение решает задачу почти в одиночку** — f1_macro 0.9375 на одном признаке.
- **Кластеризацию улучшает переход к цветовым индексам**: ARI растёт с 0.2580 до 0.3133
  при том же алгоритме. Для Random Forest замена ничего не меняет — дерево строит
  разности признаков само.

### Главные наблюдения

1. **Silhouette не подтверждает k = 3** — максимум приходится на k = 2 (0.503 против 0.443),
   инерция убывает плавно, без выраженного «локтя». То есть без подсказки из меток
   геометрия данных не выдаёт три группы.
2. **Ни один кластер не соответствует классу STAR.** Majority vote даёт GALAXY, QSO, GALAXY:
   K-Means режет вытянутое облако галактик пополам, а звёзды растворяются внутри обоих
   галактических кластеров (11 248 и 10 343 звезды из 21 593). Квазары при этом выделяются
   хорошо (purity 0.938) — за счёт большого красного смещения.
3. **Слабое место Подхода A — квазары**: recall 0.9285, их путают с галактиками.
   Звёзды отделяются почти идеально (recall 0.9995, ROC-AUC 0.9998).
4. **Данных с запасом**: кривая обучения выходит на плато уже на 20–40 тысячах объектов.
